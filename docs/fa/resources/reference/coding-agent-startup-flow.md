# جریان راه‌اندازی عامل کدنویسی

این را در شروع هر جلسه بعد از تکمیل اولیه استفاده کنید.

## الگوی راه‌اندازی ثابت

1. `pwd` را اجرا کنید و ریشه‌ی ریپازیتوری را تأیید کنید.
2. `claude-progress.md` را بخوانید.
3. `feature_list.json` را بخوانید.
4. کمیت‌های اخیر را با `git log --oneline -5` بررسی کنید.
5. `./init.sh` را اجرا کنید.
6. یک مسیر خط‌ریخت یا انتهایی را اجرا کنید.
7. اگر خط‌ریخت شکسته است، ابتدا آن را تصحیح کنید.
8. بالاترین ویژگی اولویت‌بندی‌نشده را انتخاب کنید.
9. فقط بر روی آن ویژگی کار کنید تا آن‌ها راستی‌آزمایی‌شده یا صریح مسدود شوند.

## چرا این ترتیب اهمیت دارد

- `pwd` از کار تصادفی در دایرکتوری اشتباه جلوگیری می‌کند.
- فایل‌های پیشرفت و ویژگی حالت دوام‌دار را قبل از تغییرات جدید بازیابی می‌کنند.
- کمیت‌های اخیر آخرین تغییرات را توضیح می‌دهند.
- `init.sh` راه‌اندازی را استاندارد می‌کند تا نه بر حافظه.
- راستی‌آزمایی خط‌ریخت حالت‌های شروع شکسته را قبل از اینکه کار جدید آن‌ها را پنهان کند کشف می‌کند.

## آینه انتهای جلسه

همان جلسه باید با این‌ها پایان یابد:

1. ثبت پیشرفت
2. به‌روزرسانی حالت ویژگی
3. نوشتن تحویل در صورت نیاز
4. کار ایمن را تأیید کنید
5. مسیر بازشروع تمیز بگذارید
