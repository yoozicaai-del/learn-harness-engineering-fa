# نقشه‌ی بازی عامل آماده‌کننده

این نقشه‌ی بازی را برای اولین جلسه‌ی جدی در یک ریپازیتوری استفاده کنید، قبل از شروع کار ویژگی‌های مرحله‌ای.

## هدف

یک سطح کاری پایدار ایجاد کنید تا جلسات بعدی بتوانند رفتار را اجرا کنند بدون اینکه مجدداً دستورات راه‌اندازی، وضعیت فعلی، یا مرزهای وظیفه را استخراج کنند.

## خروجی‌های الزامی

آماده‌کننده باید حداقل این عامل‌ها را جا بگذارد:

- یک فایل دستور ریشه‌ای مثل `AGENTS.md` یا `CLAUDE.md`
- یک سطح ویژگی قابل‌خوانی‌ای برای ماشین مثل `feature_list.json`
- یک عامل پیشرفت دوام‌آور مثل `claude-progress.md`
- یک کمک‌دهنده‌ی راه‌اندازی استاندارد مثل `init.sh`
- یک commit اولیه ایمن که scaffold خط بنیادی را تصویر می‌کند

## فهرست‌وار کار

1. مسیر راه‌اندازی استاندارد را تعریف کنید.
2. مسیر راستی‌آزمایی استاندارد را تعریف کنید.
3. گزارش پیشرفت را ایجاد کنید و وضعیت اولیه را ثبت کنید.
4. کار را به ویژگی‌های صریح با وضعیت‌ها تجزیه کنید.
5. اولین commit خط بنیادی پاک را ایجاد کنید.

## تست موفقیت

یک جلسه‌ی جدید بدون متن چت قبلی باید بتواند به این‌ها جواب دهد:

- این ریپازیتوری چه کار می‌کند
- چگونه آن را شروع کنید
- چگونه آن را راستی‌آزمایی کنید
- چه چیزی تمام‌نشده است
- بهترین گام بعدی چیست
