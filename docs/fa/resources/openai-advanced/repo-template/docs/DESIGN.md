# DESIGN.md

این فایل نقطه‌ی ورودی طراحی است. آن را مختصر نگه دارید و از آن برای هدایت به فایل‌های جزئی‌تر تحت `docs/design-docs/` استفاده کنید.

## هدف

تصمیمات طراحی محصول و سیستم دوام‌دار را ثبت کنید که باید از یک چت، اسپرینت یا حافظه بازبین‌کننده فراتر بروند.

## در این موارد بخوانید

- زمانی‌که به فلسفه‌ی طراحی فعلی نیاز دارید
- زمانی‌که قرار است یک الگو جدید معرفی کنید
- زمانی‌که نیاز دارید بدانید کدام تصمیمات طراحی نهایی هستند در مقابل هنوز باز

## اسناد طراحی واژه‌گانی

- `docs/design-docs/index.md`: نمایه‌ی اسناد پذیرفته‌شده، پیشنهادی و منسوخ‌شده
- `docs/design-docs/core-beliefs.md`: باورهای اول‌دست عامل برای تمام پروژه

## قوانین طراحی

- اسناد طراحی را کوچک و جاری نگه دارید.
- یک سند برای هر ناحیه‌ی تصمیم ترجیح دهید.
- اسناد طراحی را از طرح‌ها و مشخصات پیوند دهید زمانی‌که تغییری به آن‌ها بستگی دارد.
- اگر قانون طراحی از نظر عملیاتی حیاتی شود، آن را به یک بررسی خودکار ارتقا دهید یا `ARCHITECTURE.md` را به‌روز کنید.
