# FRONTEND.md

این فایل انتظارات واجهه‌ی کاربری پایدار را تعریف می‌کند تا عوامل الگوهای UI را به‌طور غیرمنتظره‌ای اختراع نکنند.

## اصول واجهه‌ی کاربری

- وضوح را قبل از نوآوری ترجیح دهید.
- جریان‌های تعامل را قابل‌کشف و قابل بازشروع نگه دارید.
- تعداد کمی از اجزای قابل استفاده مجدد را بر متغیرهای تک‌استفاده ترجیح دهید.
- بررسی‌های دسترسی‌پذیری بخشی از راستی‌آزمایی معمولی هستند، نه کار پالایش.

## حفاظ‌ها

- سیستم طراحی یا کتاب‌خانه‌ی اجزا را در `docs/references/` مستند کنید.
- حالت‌های رو به کاربر کلیدی را ثبت کنید: خالی، در حال بارگذاری، موفقیت، خطا، تکرار.
- کپی، رفتار صفحه‌کلید و سلسله‌مراتب بصری را در تمام جریان‌ها ثابت نگه دارید.
- وقتی یک خطای UI رفع شود، مرحله‌ی راستی‌آزمایی مطابقت را اضافه یا به‌روز کنید.

## انتظارات راستی‌آزمایی

- شواهد را برای سفرهای کاربری حیاتی ثبت کنید.
- مراحل راستی‌آزمایی مرورگر یا اجرا را در طرح مرتبط ثبت کنید.
- اگر رگرسیون‌های بصری رایج هستند، بررسی‌های اسکرین‌شات یا DOM را استاندارد کنید.
