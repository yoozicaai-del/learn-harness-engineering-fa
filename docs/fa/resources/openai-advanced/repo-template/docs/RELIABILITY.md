# RELIABILITY.md

این فایل تعریف می‌کند که چگونه سیستم ثابت می‌کند که سالم است و قابل بازشروع.

## مسیرهای استاندارد

- بوت‌استرپ: `[دستور]`
- راستی‌آزمایی: `[دستور]`
- شروع برنامه یا سرویس: `[دستور]`
- اشکال‌یابی یا بررسی اجرا: `[دستور]`

## سیگنال‌های Runtime لازم

- گزارش‌های ساختار‌یافته برای شروع و جریان‌های حیاتی
- بررسی‌های سلامت برای سرویس‌های کلیدی
- داده‌های ردیابی یا زمان‌بندی برای مسیرهای آهسته در دسترس
- حالت‌های خطای دیدنی برای کاربر برای شکست‌های بازیابی‌پذیر

## سفرهای طلایی

- `[سفر 1]`
- `[سفر 2]`
- `[سفر 3]`

هر سفر طلایی باید یک مسیر راستی‌آزمایی تکراری و سیگنال‌های شکست واضح داشته باشد.

## قوانین قابلیت اطمینان

- هیچ ویژگی کامل نیست اگر سیستم نتواند بعد از آن به‌طور تمیز بازشروع شود.
- شکست‌های اجرا باید از سیگنال‌های محلی ریپازیتوری قابل تشخیص باشند.
- اگر یک حالت شکست تکراری ظاهر شود، یک معیار یا حفاظ برای آن اضافه کنید.
- پاکسازی بخشی از قابلیت اطمینان است، نه یک نگرانی جداگانه.
