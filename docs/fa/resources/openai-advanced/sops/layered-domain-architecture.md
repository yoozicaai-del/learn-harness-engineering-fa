# SOP: معماری لایه‌ای دامنه

این SOP را زمانی استفاده کنید که عامل بار و بار مرزها را نقض می‌کند، منطق را در سراسر لایه‌ها تکثیر می‌کند یا کد تولید می‌کند که بعد از چند جلسه بررسی کردن دشوار می‌شود.

## هدف

مرزهای دامنه را به‌قدری صریح کنید که عوامل می‌توانند بدون تنزل خاموش ساختار سریع حرکت کنند.

## مدل هدف

در یک دامنه‌ی تجاری، جریان جهت‌دار این را ترجیح دهید:

`Types -> Config -> Repo -> Service -> Runtime -> UI`

مسائل فراگیر باید از طریق ارائه‌دهنده‌ها یا تطبیق‌کننده‌های صریح وارد شوند. ابزارهای مشترک خارج از دامنه باقی می‌مانند و نباید منطق دامنه‌ای جمع کنند.

## چک‌لیست تنظیم

- دامنه‌های جاری را در `ARCHITECTURE.md` تعریف کنید.
- جهت‌های وابستگی مجاز را در `ARCHITECTURE.md` ثبت کنید.
- رابط‌های فراگیر مانند auth، تلمتری و API‌های خارجی را ثبت کنید.
- یک یادداشت کوتاه برای سخت‌ترین نقض مرز فعلی اضافه کنید.
- تصمیم بگیرید که چه باید به‌صورت مکانیکی توسط lint، تست یا اسکریپت اعمال شود.

## SOP اجرا

1. پیش از لمس کردن سبک اجرا، کدگذار را به دامنه‌ها نقشه کنید.
2. برای هر دامنه، دنباله‌ی لایه‌ی مجاز را شناسایی کنید.
3. تمام مسائل فراگیر را شناسایی کنید و آن‌ها را از طریق ارائه‌دهنده‌ها یا تطبیق‌کننده‌ها هدایت کنید.
4. منطق مشترک ابهام‌انگیز را به دامنه‌ی مالک یا ابزارهای واقعی عمومی منتقل کنید.
5. قوانین را در `ARCHITECTURE.md` مستند کنید.
6. یک حفاظ اجرایی برای بالاترین نقض هزینه اضافه کنید.
7. نمره‌ی کیفیت را بعد از تغییر به‌روز کنید.

## تعریف تکمیل

- یک عامل تازه می‌تواند کدام لایه یک تغییر را مالک است بگوید.
- کد UI دیگر به مخازن یا اثرات جانبی خارجی دسترسی ندارد.
- مسائل فراگیر نقاط ورودی نام‌گذاری‌شده دارند.
- حداقل یک مرز مهم به‌صورت مکانیکی اعمال شده است.
